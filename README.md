# Бюро — сайт студии

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4. Анимации — CSS + один IntersectionObserver + лёгкий параллакс на rAF; Motion/GSAP не понадобились (меньше JS, лучше INP).

## Языки (i18n)

9 языков: ru, en, de, fr, es, sr (латиница), hi, zh-cn, ja. URL: `/ru/`, `/en/`, …; `/` — x-default.

- **Определение языка** (`src/proxy.ts`): сохранённый выбор (cookie `NEXT_LOCALE`) → `Accept-Language` → английский. IP/страна не используются. В статическом превью то же делает скрипт на `/` по `navigator.languages` + localStorage.
- **Словари**: `src/i18n/dictionaries/<lang>.ts`. Русский — исходный; остальные проверяются типом `satisfies Dict`, поэтому непереведённый ключ = ошибка сборки.
- **ICU MessageFormat**: `src/i18n/format.ts` (`{var}`, `{n, plural, …}` через `Intl.PluralRules`).
- **SEO**: `hreflang` для всех языков + `x-default`, canonical, локализованные title/description, `lang` у `<html>`, sitemap с alternates.
- **Новый язык** (например, другие языки Индии): добавить запись в `src/i18n/config.ts`, словарь и при необходимости шрифт/правила в `globals.css` (`:lang(...)`).
- Шрифты: Unbounded/Onest (кириллица, латиница, латиница-ext), Noto Sans Devanagari для хинди; для китайского и японского — системные шрифты (PingFang, Hiragino, YaHei, Noto CJK), чтобы не грузить мегабайты.

## Калькулятор стоимости (`/<lang>/calculator/`)

Выбор услуг → объём → опции и параметры → смета → PDF и бриф.

- **Услуги** — ровно те 8, что в разделе «Услуги» сайта (`services.items` в словарях): названия, описания и пункты «Что входит» калькулятор берёт оттуда (`src/i18n/calculator/get.ts`), тест проверяет совпадение на всех языках. Для услуг и пунктов без цены в прайсе (мобильные приложения, брендинг, digital-продукты; полиграфия, упаковка, мерч) — индивидуальная оценка, в сумму не входят.
- **Прайс** — `src/lib/calculator/catalog.ts`. Цены и коэффициенты сложности/срочности перенесены 1:1 из рабочего калькулятора (репозиторий `kishalov-price`) без внутренних данных (доли исполнителей, минимальный чек). Меняете цену в одном проекте — поменяйте и в другом: `engine.test.ts` сверяет прайс с исходным.
- **Расчёт** — `src/lib/calculator/engine.ts`: стоимость (Σ цена × кол-во × сложность × срочность) и сроки. Разные направления идут параллельно (берётся самый длинный поток), концепция и ресёрч — до, правки — после. Нормы сроков в каталоге — стартовые, их стоит сверить с реальной практикой.
- **Валюта** — USD, как в исходном прайсе. Курсы не пересчитываются, меняется только формат записи под язык.
- **Тексты** — `src/i18n/calculator/<lang>.ts` (9 языков, проверка через `satisfies CalcDict`).
- **PDF** — `POST /api/quote-pdf/`, собирается на сервере (`@react-pdf/renderer`, шрифты в `assets/pdf-fonts`), стоимость пересчитывается сервером. В браузер библиотека не грузится.
- **Бриф** — `POST /api/brief/` (контракт в комментарии роута, схема — `src/lib/brief/schema.ts`). Уходит в тот же Telegram-бот и чат, что и заявки из форм (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; транспорт — `src/lib/brief/transports/telegram.ts`), длинный бриф делится на несколько сообщений. Без этих переменных роут отвечает 503, а кнопка отправки на странице выключена с пояснением. Другие каналы — ещё один транспорт в `src/lib/brief/delivery.ts`.
- **Повторные обращения** — нормализация телефона/email/Telegram, хэш-ключи клиента и отпечаток проекта (`src/lib/brief/dedupe.ts`), идемпотентность по ключу запроса. Сейчас хранилище — память процесса (защищает только от двойной отправки); для распознавания повторных клиентов подключите постоянную реализацию `BriefStore` в `getBriefStore()`.
- **Тесты** — `npm test` (Node test runner + tsx).

## Маскот

Исходники — 3D-рендеры из ролика, 5 эмоций: `public/mascot/<emotion>-{360,640,full}.{avif,webp}`. Звезда на животе перекрашена в фирменный коралл. Компонент: `src/components/mm/Mascot.tsx`.

| Эмоция | Где |
|---|---|
| happy | первый экран, успешная отправка формы |
| angry | «Знакомо?» — боли партнёров |
| think | FAQ |
| neutral | выглядывает из-за формы в контактах |
| sad | ошибка отправки, страница 404 |

Mixed media кит (стикеры, 3D-сферы, тумблер, круглый бейдж, курсоры, пунктир, рамка выделения): `src/components/mm/Kit.tsx`.

## Запуск

```bash
npm install
cp .env.example .env.local   # заполнить переменные
npm run dev                  # http://localhost:3000
npm run build && npm start   # продакшен
```

Деплой: Vercel (импорт репозитория), переменные окружения задаются в настройках проекта.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Свой домен. На Vercel можно не задавать — берётся продакшн-адрес проекта; превью-деплои закрыты от индексации. |
| `TELEGRAM_BOT_TOKEN` | Бот, через который приходят заявки (создать в @BotFather). |
| `TELEGRAM_CHAT_ID` | Чат или группа, куда бот пишет заявки. |

Если переменные Telegram не заданы, `/api/lead` отвечает 503, а форма показывает ошибку и прямой контакт. Успешная отправка не имитируется.

## Где менять контент

Всё лежит в `src/content/`, вёрстку трогать не нужно.

- `src/content/site.ts` — контакты. Пустые (`null`) на сайте не показываются.
- `src/content/cases.ts` — языконезависимая часть кейсов (картинки, индустрия, теги).
- `src/i18n/dictionaries/*.ts` — все тексты: УТП, услуги, кейсы, отзывы, FAQ, формы, ошибки, метаданные.
- УТП взяты из таблицы «План продвижения // Бюро», вкладка «УТП для Бюро».

### Как добавить кейс

1. Сконвертируйте изображения в WebP нескольких ширин: `public/cases/<имя>-<ширина>.webp` (например, `client-cover-640.webp`, `client-cover-1200.webp`).
2. Добавьте запись в `src/content/cases.ts`: категория (`ads`, `landing`, `branding`, `motion`), обложка (`collage` — веер работ, `browser` — сайт в окне браузера с прокруткой при наведении, `video` — ролик) и галерея.
3. Добавьте тексты в `cases.items` каждого словаря: название, клиент, кратко, задача, решение, подписи к изображениям. Сборка не пройдёт, пока тексты есть не во всех языках.
4. В `results` пишите только подтверждённые цифры. Формат сотрудничества (`format`) указывайте, только если он известен.

Сейчас на сайте 12 реальных кейсов: Telegram Mini App для доставки еды (первым), редизайн сайта стоматологии (бренд под NDA), баннеры для застройщиков (японский — первым), таргет-креативы, лендинги InOut, Cape Caviar и Angelaw, брендинг Biomavital, Nibble и Petal Punk, моушн-ролики (pepperpromo — первым) и анимация логотипа «Мастерской Руслана Сафина».

### Отзывы

Сейчас все отзывы — сгенерированные примеры, на сайте помечены «Пример отзыва» (бейдж в `Testimonials.tsx`). Перед публикацией замените тексты в `reviews.items` реальными (с согласия авторов) и уберите бейдж.

### Кейс-презентация (готовые слайды)

Если у кейса есть готовые слайды (как у Telegram Mini App), задайте в `src/content/cases.ts`
`presentation: { hero, results, outro }`, `layout: "showcase"` и `results` (доли: 0.38 = +38 %).
Слайды показываются в исходных пропорциях в AVIF/WebP (`avif: true` у картинки); оригиналы — в `assets/originals/`.
Подписи метрик, итог и текст финального CTA — в словарях: `cases.items[slug].metrics / outcome / ctaTitle / ctaText`.

## SEO, иконки и превью для соцсетей

- **Адрес сайта** — `NEXT_PUBLIC_SITE_URL`. На Vercel можно не задавать: берётся продакшн-адрес проекта. Индексация включена только на продакшне; превью-деплои закрыты `noindex`.
- **Мета** — `src/lib/seo.ts`: canonical, hreflang (+ x-default), Open Graph и Twitter для каждой страницы, JSON-LD (Organization, у кейсов — CreativeWork и BreadcrumbList).
- **Иконки** — `src/app/favicon.ico` (16/32/48), `icon0.svg` (векторная, из глифа Unbounded), `icon1.png`, `apple-icon.png`; для PWA — `public/icon-192.png`, `icon-512.png`, `icon-maskable-512.png` и `src/app/manifest.ts`. Пересобрать SVG: `scripts/og/icon_svg.py`.
- **OG-картинки** — `public/og/home-<язык>.png` (9 языков) и `public/og/case-<кейс>.jpg`. После нового кейса или смены заголовка:
  ```bash
  npm run build && npx next start -p 3100 &
  npx tsx scripts/og/dump-texts.ts > /tmp/og-texts.json
  python3 scripts/og/generate.py http://localhost:3100 /tmp/og-texts.json public/og            # все
  python3 scripts/og/generate.py http://localhost:3100 /tmp/og-texts.json public/og case-nibble # одну
  ```
- Проверить превью после деплоя: [opengraph.xyz](https://www.opengraph.xyz/), в Telegram — через @WebpageBot (сбрасывает кэш ссылки).

## Дизайн-токены

Источник — Brand Guidelines v1.0. Токены лежат в `src/app/globals.css` (`@theme`): цвета, шрифты, брейкпоинты, радиусы, типографическая шкала (`.t-display … .t-mono`). Шрифты Unbounded, Onest и JetBrains Mono подключены локально из `public/fonts` (только кириллица и латиница).

Что отличается от брендбука и почему:
- Добавлен `stone-ink` (#5F5A52) для мелкого вторичного текста: «Камень» #8C867B на «Бумаге» не проходит WCAG AA.
- Синий не используется, потому что брендбук запрещает сочетать его с кораллом.

## Английская версия
